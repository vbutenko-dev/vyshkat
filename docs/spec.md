# Спецификация: «ВышКат»

Автор: Бутенко Владислав Алексеевич, БПИ252 (КПО БПИ254).
Дата: 2026-10-25.

## 1. Цель

Программа ведёт учёт транспорта и вещей на балансе проката.
Пользователь добавляет объекты, получает отчёты и выбирает транспорт для новичков.
Решение показывает применение SOLID, внедрения зависимостей и юнит-тестов на Go.

## 2. Границы версии

В версии доступны электросамокат, велосипед, электровелосипед, шлем и зарядная станция.
Данные хранятся в памяти одного процесса.
Учёт аренды, сотрудников, остатков склада и сохранение на диск не реализованы.
Приложение работает последовательно через консоль.

## 3. Команды и ввод

Каждый ответ вводится отдельной строкой. Названия могут содержать пробелы.
Дробные числа используют точку. Исправность задаётся словами `да` или `нет`.

| Команда | Ввод после команды | Вывод при успехе |
| --- | --- | --- |
| `1` | Вид транспорта, название, номер, простота, энергия для электрического вида, исправность | Подтверждение приёмки |
| `2` | Вид вещи, название, номер, энергия для станции | Подтверждение постановки на баланс |
| `3` | Нет | Количества транспорта, вещей и всех объектов. Энергия каждой категории и общая сумма |
| `4` | Нет | Название, номер и простота каждого подходящего транспорта |
| `5` | Нет | Названия и номера всех учтённых объектов |
| `0` | Нет | Завершение программы |

В команде `1` виды обозначены числами: `1` — электросамокат, `2` — велосипед, `3` — электровелосипед.
В команде `2`: `1` — шлем, `2` — зарядная станция.
Велосипед и шлем не требуют поля энергии.

Неизвестная команда вызывает сообщение и повтор меню.
При неверном формате числа повторяется ввод этого поля.
Нарушение диапазона или правил карточки вызывает отказ после её заполнения.
Программа показывает причину и возвращается в меню.
Конец ввода завершает работу без добавления незавершённого объекта.
Ошибка чтения возвращается вызывающему коду.

## 4. Функциональные требования

### FR-1. Создание объектов

Название и инвентарный номер обязательны.
Пробелы по краям удаляются до проверки на пустоту.
Простота транспорта — целое число от 1 до 10 включительно.
Энергия — конечное число не меньше нуля в кВт·ч за сутки.
`NaN` и обе бесконечности недопустимы.

Неисправность не делает карточку некорректной.
Решение о приёмке такой карточки относится к техосмотру.

### FR-2. Приёмка транспорта

Парк проверяет карточку и свободный номер до обращения к техосмотру.
Базовый техосмотр принимает исправный транспорт и отклоняет неисправный.
Отказ содержит причину «транспорт неисправен».
Парк следует внедрённому решению техосмотра.

Только положительное решение добавляет транспорт в коллекции и реестр номеров.
При отказе состояние сохраняется. Отклонённый объект не занимает номер.
Добавление транспорта через операцию для вещей запрещено.

### FR-3. Вещи и номера

Вещь добавляется после проверки карточки и номера.
Реестр номеров общий для транспорта и вещей.
Сравнение регистрозависимое: `S-001` и `s-001` различаются.
Повторный номер вызывает отказ без изменения прежнего объекта.

### FR-4. Отчёт

Отчёт показывает количество принятого транспорта, вещей и всех объектов.
Он суммирует суточную энергию через интерфейс `EnergyConsumer`.
Пустой парк даёт нулевые количества и суммы.
Повторный вызов отчёта не меняет парк и не запускает техосмотр.

Общая сумма включает энергию транспорта и вещей.
Станция сообщает собственный расход, чтобы не учитывать энергию транспорта дважды.
Это выбранная трактовка энергопотребления парка в учебной модели.
Консоль показывает энергию с тремя знаками после точки.

### FR-5. Подбор для новичков

Подходят принятые транспортные средства с простотой не ниже 6.
Оценка 5 исключается, оценка 6 включается.
Вещи и отклонённый транспорт в результат не входят.
Порядок совпадает с порядком приёмки.

### FR-6. Инвентаризация

Инвентаризация показывает название и номер каждого объекта на балансе.
Методы сервисов возвращают новые срезы.
Замена элемента такого среза не меняет внутренний список.
Сами объекты при этом не копируются.

## 5. Сценарии приёмки

### Пример успешной приёмки

В новом процессе введите строки:

```text
1
1
ВышКат S1
S-001
6
1.5
да
3
0
```

Первые два числа выбирают добавление транспорта и вид «электросамокат».
Среди приглашений и меню должны появиться строки:

```text
Транспорт принят в парк: ВышКат S1 (S-001).
Транспорт: 1
Вещи: 0
Всего: 1
Энергия транспорта: 1.500 кВт·ч/сутки
Энергия вещей: 0.000 кВт·ч/сутки
Общая энергия: 1.500 кВт·ч/сутки
```

При замене `да` на `нет` базовый техосмотр откажет с причиной неисправности.
Последующий отчёт останется нулевым.

### Дополнительные случаи

| Сценарий | Ожидаемый результат |
| --- | --- |
| Запрос отчёта до добавления объектов | Нулевые количества и энергия |
| Исправный самокат, простота 6, энергия 1.5 | Принят. Есть в отчёте, инвентаризации и списке новичков |
| Исправный велосипед с простотой 5 | Принят. Энергию не увеличивает, новичкам не предлагается |
| Неисправный транспорт при базовом техосмотре | Отказ с причиной. Парк и реестр номеров не изменились |
| Вещь с номером уже принятого транспорта | Отказ по общему реестру |
| Повторное использование номера отклонённого транспорта | Допустимо, если новая приёмка проходит проверки |
| Пустое название, простота 11 или энергия -1 | Отказ по данным карточки |
| Нечисловой ответ в поле простоты | Повтор вопроса |
| Конец ввода посреди карточки | Завершение без добавления объекта |
| Подставной техосмотр в тесте | Парк следует его решению и передаёт ему транспорт |

[examples/demo.txt](../examples/demo.txt) проверяет сквозной сценарий через консоль.
Его итог: 3 транспорта, 2 вещи, 5 объектов, 4.500 кВт·ч за сутки.
Список для новичков содержит `S-001` и `E-001`.

## 6. Ограничения реализации

Модуль `vyshkat` использует Go 1.22.0 и `go.uber.org/dig v1.19.0`.
Контейнер находится только в точке сборки приложения.
Приёмку можно тестировать с подставным техосмотром без контейнера.
Консоль принимает `io.Reader` и `io.Writer` для воспроизводимых тестов.

Тесты используют стандартный пакет `testing`.
Целевой порог покрытия из задания — не ниже 60%.
Команды проверки и ожидаемое демо описаны в [руководстве](CHECK_AND_SUBMIT.md).
