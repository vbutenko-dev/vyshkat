# ADR-0001: интерфейсы и композиция модели

Дата: 2026-10-25.
Статус: принято.

## Контекст

У транспорта и вещей есть название и инвентарный номер.
Только транспорт имеет простоту и исправность.
Некоторые объекты потребляют электрическую энергию.
Go не использует наследование классов.

## Решение

Выделить `InventoryItem`, `Vehicle` и `EnergyConsumer` по назначению.
`Vehicle` включает контракт `InventoryItem`.
Конкретные структуры включают общие компоненты данных через композицию.
Конструкторы проверяют характеристики и возвращают ошибку при нарушении правил.

Поля компонентов закрыты для других пакетов.
Нулевое значение экспортированной структуры не считается готовой карточкой.
Приёмка повторно проверяет входные реализации интерфейсов.

## Альтернативы

- Один общий интерфейс потребовал бы энергии у велосипеда и шлема.
- Повторение всех полей и методов в каждом типе увеличило бы дублирование.
- Одна структура с полем вида потребовала бы проверок вида в правилах модели.

## Последствия

Отчёты используют возможности объектов через интерфейсы.
Новый вид транспорта можно добавить без изменения приёмки и расчётов.
Консольный выбор конструкторов придётся дополнить отдельно.
Корректность данных обеспечивают конструкторы и граница приёмки, а не само объявление интерфейса.
