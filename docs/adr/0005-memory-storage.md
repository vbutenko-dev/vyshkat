# ADR-0005: учёт в памяти сервиса парка

Дата: 2026-10-25.
Статус: принято.

## Контекст

Текущая версия показывает приёмку и отчёты в одном запуске консольной программы.
Требование сохранять данные между запусками не задано.
Номера транспорта и вещей должны быть уникальны вместе.

## Решение

Хранить объекты в срезах внутри `FleetService`.
Использовать общую карту номеров для проверки дубликатов.
Сначала выполнить проверки и техосмотр, затем изменить коллекции.
Отчёт вычислять по текущим объектам при запросе, без отдельных накопленных счётчиков.

Методы чтения возвращают копии срезов.
Объекты внутри этих срезов остаются теми же объектами.

## Альтернативы

- Файл или база данных добавили бы чтение, сохранение и обработку повреждённых данных.
- Отдельные реестры транспорта и вещей не обеспечили бы общую уникальность сами по себе.
- Накопленные суммы потребовали бы синхронизации с коллекциями после каждого изменения.

## Последствия

Выход удаляет текущее состояние. Новый запуск начинает с пустого парка.
Порядок приёмки сохраняется в списках.
Внешний код не может заменить элемент внутреннего среза через возвращённый список.
Параллельный доступ к сервису в текущем приложении не используется и не обеспечивается.
